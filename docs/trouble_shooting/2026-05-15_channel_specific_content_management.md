# [2026-05-15] 채널별 독립 콘텐츠 관리 및 스마트 재생성 구현

## 1. 문제 상황 (Issue)
- **전체 재생성 강제**: 생성 결과 페이지에서 특정 채널(인스타그램, 당근마켓 등)의 문구만 다시 만들고 싶어도, 재생성 버튼을 누르면 모든 채널의 문구가 한꺼번에 다시 생성되어 이미 수정해둔 다른 채널의 데이터가 유실됨.
- **수동 수정 내용 저장 불가**: 사용자가 문구를 직접 수정할 수는 있었으나, 이를 서버에 저장하는 기능이 없어 페이지를 벗어나면 수정 사항이 초기화됨.
- **UI 직관성 부족**: 텍스트가 편집 가능한 상태인지 명확하지 않고, 재생성 중일 때의 시각적 피드백(로딩 상태)이 부족하여 사용자 경험이 저해됨.

## 2. 원인 분석 (Root Cause)
- **프론트엔드 로직 한계**: `ResultView`가 모든 채널의 데이터를 하나의 상태로 관리하고, 재생성 시 전체 생성 프로세스(Step 2)로 리다이렉트하는 구조로 설계되어 있었음.
- **API 연동 미비**: 백엔드에는 이미 `PATCH /api/v1/contents/{contentId}` API가 존재했으나, 프론트엔드 Repository 및 Data Source 레이어에서 이를 호출하는 로직이 구현되어 있지 않았음.

## 3. 해결 방안 (Solution)
### 3.1 스마트 부분 재생성 (Partial Regeneration)
- 재생성 버튼 클릭 시 페이지를 이동하지 않고, 해당 채널 카드 내에서 비동기 처리를 수행하도록 변경.
- 백엔드에 재생성 요청 후 `apiLogId`를 통해 상태를 폴링(Polling)하고, 성공 시 새로운 데이터에서 **해당 채널의 텍스트만 추출하여 업데이트**함으로써 타 채널의 기존 수정본을 보존함.

### 3.2 수동 수정 저장 기능 (Manual Save)
- 백엔드의 `ContentController.java (Line 66)`에 구현된 `updateContent` API를 프론트엔드와 연결.
- 각 채널별로 원본 데이터와 현재 입력값을 비교하여, 변경 사항이 있을 때만 **[저장하기]** 버튼을 노출하도록 상태 관리 로직 추가.

### 3.3 UI/UX 고도화
- **편집 유도 디자인**: `TextField`에 부드러운 테두리와 힌트 메시지를 추가하여 편집 영역임을 명확히 함.
- **로딩 피드백**: 저장 및 재생성 버튼 내부에 `CircularProgressIndicator`를 적용하여 작업 중임을 시각적으로 전달.
- **브랜드 컬러 적용**: 각 채널별 고유 컬러(인스타-핑크, 당근-오렌지, 네이버-그린)를 테마로 적용하여 채널 간 구분을 명확히 함.

## 4. 검증 결과 (Verification)
- [x] 인스타그램 문구 수정 후 '저장하기' 클릭 시 서버에 정상 반영됨을 확인.
- [x] 당근마켓 문구 재생성 시, 수정한 인스타그램 문구는 유지되고 당근마켓 내용만 갱신됨을 확인.
- [x] 재생성 중 버튼이 '생성 중' 상태로 변경되며 중복 클릭이 방지됨을 확인.

## 5. 향후 과제
- 현재 백엔드 전체 재생성 프로세스를 그대로 사용하고 있어 자원 소모가 발생할 수 있음. 추후 백엔드에서 특정 채널만 타겟팅하여 재생성하는 파라미터가 추가되면 프론트엔드에서도 이를 적용할 예정.
