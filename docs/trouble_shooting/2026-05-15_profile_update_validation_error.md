# [2026-05-15] 프로필 수정 시 이름 필드 누락으로 인한 400 Bad Request

## 1. 문제 상황 (Issue)
- 사용자가 프로필 수정 화면에서 **이메일만 수정**하고 저장 버튼을 눌렀을 때, 서버에서 `400 Bad Request` 에러를 반환하며 저장이 실패함.
- 오류 메시지: `"이름은 필수 입력 항목입니다."` (백엔드 유효성 검사 실패)

## 2. 원인 분석 (Root Cause)
- **백엔드 제약 조건**: `UpdateUserProfileRequest` DTO의 `name` 필드에 `@NotBlank` 어노테이션이 설정되어 있어, 수정 요청 시 이름 값이 반드시 포함되어야 함.
- **프론트엔드 전송 방식**: 기존 코드는 변경된 필드만 서버에 전송하도록 최적화되어 있었음. 따라서 이메일만 수정할 경우 `name` 필드가 누락된 채 요청이 전송됨.

## 3. 해결 방안 (Solution)
- `ProfileEditScreen`의 저장 로직을 수정하여, **이름(name) 필드 값이 변경되지 않았더라도 항상 현재의 값을 요청 본문에 포함**하도록 변경함.
- `AuthRepository` 및 API 호출 레이어에서 프로필 업데이트 시 필수 필드인 `name`과 `email`이 모두 전송되도록 보장함.

## 4. 검증 결과 (Verification)
- [x] 이름은 그대로 두고 이메일만 변경하여 저장 시 정상적으로 처리됨을 확인.
- [x] 변경된 이메일로 인증 토큰이 재발급되어 로그인이 유지됨을 확인.

## 5. 학습 포인트
- 부분 업데이트(PATCH)를 지원하는 API라 하더라도, 서버 측 DTO 설계에 따라 필수 값이 존재할 수 있음을 유의해야 함. 클라이언트와 서버 간의 데이터 스키마 합의가 중요함.
