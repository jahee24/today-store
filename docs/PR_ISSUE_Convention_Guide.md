# 📌 오늘의 가게(Today Store) GitHub PR & Issue 컨벤션 가이드

이 문서는 **오늘의 가게 프로젝트용 GitHub Issue 및 Pull Request 작성 컨벤션 가이드**입니다. 모든 팀원은 아래 규칙을 준수하여 명확하고 일관된 협업 환경을 유지해주세요!

---

## 1. Issue 생성 컨벤션

새로운 작업을 시작하거나 버그를 발견했을 때 Issue를 먼저 생성합니다. 각 목적에 맞는 알맞은 템플릿을 선택하여 생성해주세요.

### 🏷️ 이슈 타입 (Type & Labels)
*   ✨ `[Feat]`: 새로운 기능 추가 (Label: `✨ feature`)
*   🔧 `[Fix]`: 버그 수정 (Label: `🔧 fix`)
*   ♻️ `[Refactor]`: 코드 리팩토링 (기능 변경 없음) (Label: `♻️ refactor`)
*   📝 `[Docs]`: 문서 수정 (Label: `📝 docs`)
*   🛠 `[Build]`: 빌드 설정, 의존성 패키지 수정 등 (Label: `🛠 build`)

### 📝 이슈 작성 포맷
**제목 (Title)**: `[분류] 작업할 내용` (예: `[Feat] 사용자 로그인 API 구현`)

**본문 (Body)**:
```markdown
## 어떤 기능/작업인가요?
> 개발/수정하려는 기능에 대해 간결하게 설명해주세요.

## 작업 상세 내용 (TODO)
- [ ] 구체적인 작업 항목 1
- [ ] 구체적인 작업 항목 2
- [ ] 구체적인 작업 항목 3

## 참고 자료 및 메모 (선택)
관련된 노션(Notion) 링크, 디자인 시안(Figma), 기술 블로그 링크 등을 첨부합니다.
```

---

## 2. Pull Request (PR) 작성 컨벤션

작업된 코드를 리뷰받고 Merge하기 위해 PR을 생성합니다. PR 본문을 통해 리뷰어가 어떤 점을 중점적으로 봐야 할지 명확하게 전달하는 것이 중요합니다.

### 🏷️ PR 제목 포맷
**제목 (Title)**: `[분류] PR 제목` (예: `[Feat] 사용자 소셜 로그인 기능 추가`)

### 📝 PR 작성 포맷 (본문 작성 가이드)

```markdown
## Issue Number
closed #이슈넘버 (예: closed #12)

## As-Is
<!-- 현재/수정 전 문제 상황이나 상태를 정의합니다 -->
- 기존에는 OOO 기능이 없어서 OOO 방식이 불가능했습니다.

## To-Be
<!-- 이번 PR을 통해 어떻게 해결/변경되었는지 설명합니다 -->
- OOO 기능이 추가되어 정상 작동합니다.

## Check List
PR 올리기 전에 아래 항목들을 확인해주세요.
- [ ] 테스트가 전부 통과되었나요?
- [ ] 모든 commit이 push 되었나요?
- [ ] merge할 branch를 확인했나요? (예: `main`이 아닌 `develop` 등)
- [ ] Assignee(담당자)를 지정했나요?
- [ ] Label(라벨)을 지정했나요?
- [ ] 닫을 이슈 번호(Issue Number)를 연결했나요?

## (Optional) Additional Description
<!-- 추가적인 설명이나 리뷰어에게 묻고 싶은 내용 등을 자유롭게 적어주세요. -->
```

## 3. 작업 흐름 (Workflow) 가이드: Issue부터 PR까지

실제 개발을 진행할 때 이 규칙을 따라주세요.

### Step 1. Issue 생성
새로운 작업을 시작하기 전에 깃허브에서 **Issue를 생성**합니다.
*   앞서 설명한 템플릿 중 하나(Feat, Fix 등)를 선택하여 내용을 작성합니다.
*   이슈가 생성되면 고유한 **이슈 번호(#)** 가 부여됩니다. (예: `#12`)

### Step 2. Branch 생성 및 작업
이슈 번호를 기반으로 작업을 진행하되, 브랜치 이름은 작업 내용을 직관적으로 알아볼 수 있게 짓습니다.
*   **브랜치 이름 규칙**: `타입/기능-요약` 또는 `타입/#이슈번호-기능요약` 
*   (예: `feat/login-api`, `fix/navbar-css`, `feat/#12-login-api`)
*   터미널에서 명령어: `git checkout -b feat/login-api`

### Step 3. Commit 작성
작업을 코드로 작성한 후, 변경사항을 커밋합니다.
*   **커밋 메시지 규칙**: `타입: 커밋 제목 (#이슈번호)`
*   터미널에서 명령어: `git commit -m "feat: 사용자 로그인 API 구현 (#12)"`
*   커밋 메시지에 이슈 번호를 적으면 깃허브에서 해당 이슈와 커밋이 자동으로 연결됩니다.

### Step 4. PR (Pull Request) 생성 및 머지
작업이 완료되면 원격 저장소로 `push`하고 PR을 올립니다.
*   터미널 명령어: `git push origin feat/#12`
*   깃허브에 접속하여 **Compare & pull request** 버튼을 누릅니다.
*   앞서 설명한 PR 작성 컨벤션(템플릿)에 따라 PR 본문을 작성합니다.
*   특히 `closed #12`와 같이 적어두면 PR이 머지(Merge)될 때 해당 이슈가 **자동으로 닫힙니다(Closed)**.
*   팀원들의 코드 리뷰를 받고 승인(Approve)되면 `develop` 브랜치에 Merge 합니다!
